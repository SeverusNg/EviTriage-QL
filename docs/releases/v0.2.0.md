# EviTriage-QL v0.2.0

Released: 2026-07-23

EviTriage-QL v0.2.0 adds fail-closed multi-provider credential handling to the
optional DeepSeek path while retaining the bounded offline research workflow
from v0.1.0. The model adapter remains fixed to DeepSeek's official HTTPS
endpoint, and no component automatically dismisses an upstream alert.

## Added

- Independent `CredentialProvider` and `CredentialResolver` boundaries.
- Current-process `DEEPSEEK_API_KEY`, fixed TPM2/systemd-creds, and fixed
  pass/GPG providers.
- `triage --credential-provider environment|systemd-creds|pass|auto`, with
  fixed auto order `environment → systemd-creds → pass`.
- Non-secret `credentials status --json` output and hidden double-prompt
  `credentials set-deepseek --provider pass` enrollment.

## Security properties

- Explicit provider selection never falls back. Auto skips only unavailable
  providers and stops on malformed, unsafe, or undecryptable selected state.
- Pass uses the validated fixed `evitriage/deepseek-api-key` entry, fixed argv,
  `shell=False`, standard-input enrollment, bounded output, a timeout, and a
  pwd-derived minimal child environment.
- The pass executable must be a non-symlink regular executable owned by root or
  the current user and not group/world writable.
- Tests use fake command runners and simulated HTTPS. They do not invoke real
  pass, GPG, systemd decryption, or DeepSeek and do not load operator keys.

## Operational guidance

WSL users should prefer pass/GPG with a passphrase-protected GPG private key or
a one-process environment key. Native Linux users can continue using the
TPM2/systemd-creds backend. Secret Service/Python keyring is not treated as a
reliable default for headless sessions.

GPG-agent may cache the unlocked private-key capability, allowing same-user
processes to use it until cache expiry. TPM2, pass/GPG, and environment
handling protect only the API key: source excerpts and evidence are still sent
to DeepSeek after both trusted policies explicitly declare
`remote_llm_allowed`.

No “absolute security” is claimed. Root or same-user inspection, an unlocked or
compromised gpg-agent, a compromised runtime, provider compromise, and
centralized secret management remain outside this release boundary.

## Release evidence

The release workflow reruns `make check`, `make security-test`, the deterministic
offline six-case Replay demo, release-artifact assembly and verification, and a
source-distribution reinstall. The generated release directory contains the
wheel, source distribution, locked dependency inventory, CycloneDX SBOM,
machine-readable test summaries, reviewed demo evidence, strict manifest, and
`SHA256SUMS`.

This remains research infrastructure, not a production vulnerability
classifier or model-quality benchmark. See
[`KNOWN_LIMITATIONS.md`](../../KNOWN_LIMITATIONS.md) and
[`docs/reproducibility.md`](../reproducibility.md).
