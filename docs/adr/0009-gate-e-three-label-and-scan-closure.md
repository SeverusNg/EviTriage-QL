# ADR 0009: Close Gate E with identity-bound evidence and both triage inputs

- Status: Accepted
- Date: 2026-07-23
- Gate: E (P0 vertical closure)

## Context

Gate E requires the complete `ingest/scan → normalize → context → triage →
report` path plus auditable TP, FP, and NMC examples. The base Gate C extractor
intentionally records only source and CodeQL path facts. Those neutral facts are
not sufficient to manufacture a decisive guard for FP or the independent
source-control and sink-semantics evidence required for TP. Weakening the Gate D
policy or encoding labels in demo-only code would make the examples circular.

The original `triage` command also accepted only an existing SARIF file. A real
CodeQL runner existed, but the scan branch stopped at `CONTEXT_READY` instead of
continuing through the same Agent, policy, and report stages.

## Decision

1. `triage` requires exactly one of `--sarif` or `--scan`. The scan form creates
   the CodeQL database, preserves the actual analyzer SARIF, and continues in
   that same run through normalization, context, evidence, all three Agent
   stages, deterministic policy, reports, and finalization. Both forms use the
   shared strict normalizer and report builder.
2. Existing-SARIF triage may accept an optional trusted
   `--evidence-supplement` JSON artifact. Its strict public schema binds the
   assertions to the exact project ID, repository snapshot SHA-256, raw SARIF
   SHA-256, and `(run_index, result_index)` occurrence. Duplicate occurrences,
   unknown fields, traversal/symlink input, identity mismatches, and invalid
   decisive-neutral assertions fail as `POLICY_REJECTED`.
3. The supplement contains evidence assertions, not Claims or desired labels.
   The pipeline assigns content-addressed evidence IDs, registers the original
   supplement as an immutable input artifact, records its producer/purpose,
   merges the assertions into the closed Evidence Registry, and still requires
   ordinary Agent schemas and deterministic TP/FP/NMC gates.
4. `make demo` uses three original Apache-2.0 Java microcases, one Golden SARIF
   with three exact result occurrences, a fixture-bound test-evidence
   supplement, and nine request-hash-addressed Replay responses. The resulting
   strict JSONL has one TP, one decisive FP, and one NMC row; HTML and the run
   manifest are generated by the normal production path. No response or label
   is generated during the demo.

## Consequences

- Gate E's P0 offline vertical requirements now have executable coverage:
  `make demo` is network-free and produces TP, FP, and NMC reports, while a
  controlled-runner integration test proves `--scan` continues through the
  same `JUDGED` report path.
- Supplemental evidence makes the trust boundary visible and auditable without
  claiming that an operator or synthetic fixture assertion is independently
  true. Production users remain responsible for evidence provenance; automatic
  verification and human-label workflows are later scope.
- The demo is deterministic workflow/policy evidence, not a benchmark, model
  quality result, calibrated score, or vulnerability verdict about arbitrary
  code. Its TP/FP assertions are synthetic test oracles.
- A fresh real CodeQL `triage --scan` still requires pinned external tools and a
  Replay cache matching that scan's exact requests (or an explicitly allowed
  remote provider). No new live scan-to-`JUDGED` artifact is claimed here.
- Prior-run continuation, a standalone `report --run-id` command, a general
  Replay cache producer/attestation service, CSV/cross-run aggregation,
  verification, and calibration remain outside the Gate E P0 closure.
