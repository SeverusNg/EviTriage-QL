## Frozen v0.1 contract

The mandatory vertical slice remains:

```text
Java fixture / golden SARIF
→ CodeQL or SARIF ingest
→ SARIF/codeFlows normalize
→ path-function context
→ evidence registry
→ Analyst / Rebuttal / Judge
→ deterministic policy
→ TP / FP / NMC
→ JSONL + HTML report
```

Gate A establishes the engineering, ProjectSpec, workspace, diagnostics,
storage, and CI substrate. The 2026-07-21 entry additionally delivers the two
Gate B input branches through `SARIF/codeFlows normalize`. Path-function
context and every later box remain undelivered by this log.

The following work cannot be traded away from v0.1: strict schemas,
evidence/claim reference gates, NMC, Fake/Replay, an offline end-to-end path,
tests, and a run manifest. If schedule pressure requires cuts, the order is
GitHub integration, PostgreSQL, remote clone, complete Gradle support, real model
provider, adaptive context, verification, then calibration.

#### Failures and blockers

- A first focused run exposed one stale test expectation: strict `BuildSpec`
  validation rejected bare `mvn` before the runner-specific assertion. The
  defense-in-depth test was corrected to construct an already-validated model
  copy; after subsequent provenance/security hardening, the exact focused

- No hosted CI run, Maven Wrapper distribution bootstrap, real Java/`javac`
  tool execution, or real CodeQL database/SARIF artifact is claimed by this
  entry.

#### Risks

- The runner currently starts the checked-in wrapper as the host user. Managed
  paths, a constrained environment, `shell=False`, and timeouts are useful
  boundaries, but there is no complete OS network/resource/process-tree
  sandbox; only trusted fixtures should be scanned until external isolation is
  supplied.
- Maven `--offline` does not itself prevent the wrapper launcher from
  downloading Maven when its declared-version cache is empty. Cache bootstrap
  and attestation must be a separately controlled supply-chain step.
- For existing SARIF, source-revision correspondence remains operator-supplied.
  Existing regular files are independently hashed and conflicts rejected, but
  missing files remain allowed with no verified digest, and coordinates are not
  checked against actual line/column bounds. Later evidence code must preserve
  those unknown/unverified distinctions.
- Current manifests cover input/normalization provenance, not the complete
  context/prompt/model/decision/report provenance required by the v0.1
  end-to-end workflow.
- Runs have no caller idempotency key or crash-resume path; every CLI invocation
  allocates a new run and pre-existing audit files are rejected.
